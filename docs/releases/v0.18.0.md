## Frozen authority contract

FACT is immutable snapshot evidence. REVIEW is challengeable interpretation. Equivalent artifacts may satisfy engineering purpose outside canonical filenames; starter scaffold is not completed team work. Missing search results mean bounded non-discovery, not exhaustive absence. Ambiguity or contradiction must remain explicit.

Only authoritative `corrected` or `resolved` states are closed. `confirmed`, `accepted_risk`, `deferred`, `under_discussion` and `evidence_disputed` remain open. Inspection, search, fluent reasoning, recommendations, review completion and later commits cannot silently close a finding on an earlier snapshot. Valid frozen counterevidence uses the explicit correction/disposition path.

Accepted production configuration is **shadow reasoning validation / shadow review planning**; legacy reasoning and student-visible question selection remain authoritative. Workflow and application fallback defaults remain `legacy`, so explicitly select both `shadow` inputs on deployment. v0.17 shadow validator/planner/selector/realizer contracts and evaluations remain internal evidence, with no PR5 transfer. Readiness is non-numeric coaching, not a grade or prediction. Staff may inspect persisted turns within role/section/term authority; this never grants student impersonation or draft access.

## Merge, deploy and publish

1. Apply the patch only after its read-only precheck validates every complete target and payload. Work on a release branch from the inspected main; review the diff and run validation.
2. Open a PR; require green CI and review. Merge, pull main with `--ff-only`, and confirm the actual merged SHA. Do not guess it from the candidate baseline.
3. Dispatch `deploy-azure.yml` on merged main with `reasoning_validation_mode=shadow`, `review_planning_mode=shadow`. Confirm the successful run's `headSha` matches the merged commit.
4. Run `./scripts/azure/etis-azure acceptance`. Compare live `/health.version` to `0.18.0`, both analytical modes to `shadow`, and `/ready` database/migration state to ready. Record image/revision and run URL.
5. Complete the human smoke below. If a check fails, correct the observed failure through normal review/deployment; do not certify the release.
6. Only then close the v0.18.0 Unreleased entry with the verified publication date, record acceptance evidence, and create the Git tag/GitHub release against the accepted commit. Candidate documentation alone is not production GO.

## Targeted human smoke

- Sign in as an authorized student; verify team/phase/repository context and one active review. Existing sessions retain their frozen evidence and session modes.
- Move between Review Room and Engineering Evidence. Check same-snapshot versus newer-saved-snapshot notices; an older active review remains unchanged.
- Inspect cited source and use bounded supporting-evidence discovery. Search stays in the active snapshot and exposes an action label, preserving an unsent draft.
- Challenge a false interpretation with evidence already in the frozen snapshot. Verify explicit lifecycle outcome; inspection/recommendation alone leaves an open finding open. Post-snapshot fixes require newer evidence and do not rewrite the past.
- Check Board, Focused and Findings purposes; optional context remains secondary and no readiness/finding label implies a grade.
- Use Tab/Shift+Tab and Escape in Help, artifact, challenge and exit dialogs, including nested dialogs and a pending challenge. Focus returns to a usable opener, no finish occurs on Escape, and pending work/drafts survive.
- Complete the review and open read-only history. Authorized staff see persisted turns/action labels and original snapshot context; student mutation controls and unsent drafts remain unavailable.
