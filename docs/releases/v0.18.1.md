## User-visible scope

1. Engineering Review Room (Review Board conversation) and Engineering Evidence Room (saved evidence inspection) are permanently discoverable as paired navigation; movement does not finish a review.
2. The selected Board Review is distinct from Open/Finished status. Multiple open or finished sessions remain accessible in Review History; historical pagination permits browsing past the initial page.
3. Each review preserves its captured phase, commit, snapshot and conversation. Starting another Board Review does not require finishing the current one. Identical phase/commit can reuse a frozen snapshot and does not prove new work was examined.
4. Review completion leaves a read-only preserved conversation. State-driven entry and next-action presentation prevents contradictory first-time guidance.
5. Evidence Room shows the latest **saved** phase snapshot, not live GitHub HEAD; mismatch with the selected review is explicit and an original-evidence action is available. Counters for evidence areas and Review Board findings are distinct; evidence coverage is not a grade.
6. Draft-safe navigation, viewport/composer visibility, long-conversation reading and failed-response recovery are included in the local candidate.
7. A loopback-only synthetic local simulator under tools/ exercises the same frontend without real student records, GitHub, Azure or paid models. It is not a production API or alternate evidence authority.

## Release procedure (no authority migration)

1. Confirm feature branch is based on inspected `main`, review every changed file, run `git diff --check`, targeted/full pytest, offline war games, doc hashes/render validation and CI-required checks. Never force-apply a patch over unexpected local differences.
2. Commit and push feature branch with normal user Git credentials, open a PR against `main`, obtain review and green CI. No direct main commit.
3. Merge only once gates pass; pull main `--ff-only`; capture exact merged SHA.
4. Run GitHub Actions **Deploy Azure** (`.github/workflows/deploy-azure.yml`) on that merged commit, explicitly input `reasoning_validation_mode=shadow`, `review_planning_mode=shadow` (defaults are legacy). Require successful production environment approvals and run head SHA matching merged SHA.
5. Execute the normal operator acceptance command `./scripts/azure/etis-azure acceptance`, inspect `/health` version 0.18.1 and both modes shadow, `/ready` database connected/migrations current, image/revision, and operational telemetry.
6. Human smoke: authorized student signs in; confirms team/phase/GitHub; navigates both rooms; starts/resumes an open review; switches to an older review and observes frozen commit; verifies latest phase saved evidence and original evidence differ when expected; tests Finish read-only; verifies newer review after actual repository commit; verifies no lost draft. Confirm staff access obeys section/term and does not leak private transcripts.
7. After the above, record verified source/deploy/run/acceptance details and release status. Tag and publish v0.18.1 only against the accepted deployed commit, never against local candidate files. If a gate fails, preserve v0.18.0 as production accepted and follow normal remediation/rollback.
